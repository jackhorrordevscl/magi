## Key Learnings

1. `EvaluatorSettingsSchema` composes `.optional().catch(undefined)` per field and `.catch({})` at both levels, so `safeParse`/`parse` never throws or fails on a bad field — it silently drops it. `validateFieldEdit`'s only viable "strict" implementation is drop-detection (build the candidate, parse, check whether a non-empty input round-tripped to `undefined`), never a `.success`/try-catch check, because there is no failure path to catch.
2. The `evaluators` key must be deleted from the written object (not written as `{}`) when every evaluator's fields are cleared, per design decision 5 — this keeps "unset means default" true on disk, not just in the UI, and is a distinct behavior from `normalizeEvaluators` merely omitting empty per-evaluator entries.
3. `blessed` staying out of `dist/magi.mjs` requires two mechanisms together, not either alone: `external: ['blessed']` in `esbuild.config.mjs`, AND the `import('blessed')` call site living inside `runTui()`'s function body rather than at `app.ts`'s module top — a static top-level import would still get hoisted into the module graph and load the terminal library on every `magi` invocation, not just `magi tui`.
4. Design decision 8 (read-only when `magi.config.json` is absent) is a deliberately deferred risk, not an oversight: seeding a file with only an `evaluators` key breaks `main.ts`'s `loadConfig()` for every other `magi` command because `config.paths.auditDir` would be undefined. The fix (`DEFAULT_CONFIG` export) is explicitly out of scope for this change per design.md's Open Questions.
5. `validateFieldEdit` (Slice 2, `field-edit.ts`) does NOT special-case an empty `rawInput` as "clear the field" — that resolved the apparent tension between design decision 6's prose ("reject if dropped while input was non-empty") and tasks.md 2.5's explicit `model: ''` -> rejected test case. Pure drop-detection with no empty-string carve-out satisfies both: `model: ''` fails the schema's `min(1)` and is rejected like any other invalid candidate. The "clear a field" affordance is a wholly separate mechanism — Slice 3's `d` keybinding in `app.ts` must set the field to `undefined` directly and must NEVER call `validateFieldEdit('')` to implement clearing, or it will incorrectly surface a rejection for what the operator meant as an intentional clear.
